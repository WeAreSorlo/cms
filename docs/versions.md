# Versions

Every save that changes an entry writes a version of it, numbered from 1, and records who saved it and when. The entry's panel lists its versions, newest first, and each one links to its page, `#/entries/<id>/versions/<number>`, for finding out who changed what, and when.

- **A save that changes nothing does nothing.** When the values and the parent match the entry's own, compared as they're stored so the order of keys doesn't count, a save writes no version, links or events, and leaves `updatedAt` and `updatedBy` as they were. It replies 200 with the entry as it is, and the editor says No changes. Publish still makes the newest version live when the live copy is older or missing, and bulk rows follow the same rule. A singleton that's been opened but never saved has no version yet, so its first save writes one.
- **Names.** A version is named on its page, such as Before the rebrand, in up to 100 characters, and an empty name clears it. A named version shows its name first, with its number under it.
- **Where it came from.** A version saved through the [assistant](assistant.md) or an [MCP token](mcp.md) records which, so the history says "Levi, with the assistant · 2 Nov" or "Levi, through Claude Desktop · 2 Nov", the token's name. Its last publish records the same, so it says "Published by Levi, through Claude Desktop · 2 Nov" for one through a token with Publish changes, or "Published by Levi, with the assistant" for Apply and publish, and a publish in the editor says "Published by Levi" again. A version's page links to the chat behind it, which anyone signed in can read once a version links to it. The link outlives the chat and the token, since revoking a token keeps its row and a deleted chat leaves its id, which the page says was deleted.
- **Publishes.** Each version records the last time it went live and who published it then, which the history shows as "Published by Levi · 30 Oct". Upgrading, `sorlo migrate` gives each live version its live copy's publish, the only one recorded before.
- **Comparing.** A version's page shows what it changed from the version before it, or from another picked in Compare with, the live one labelled as such, so comparing the current version with the live one shows what Publish would change. It goes from the older version to the newer, and names each changed field by its path of labels, such as SEO › Title, with what it held before and after. Long text shows the words added and removed, repeaters, flexible blocks and matrices show their items added, removed and changed, matched by position, and links show entries' titles and files' names. It opens on Show changes As JSON, which shows the two versions' values, for the more technical: JSON a line at a time, with every object's keys in order, marking the lines added and removed, and every key stored, those no field reads included. By field shows each field as above. A page's move shows first, as Parent, and its JSON holds `{ parentId, values }`, since each version records the parent it was saved under. Upgrading, `sorlo migrate` gives every existing version the parent its page has now, since nothing recorded parents before. Both versions come from the version route, brought up to date by the content migrations that ran since, so a renamed field doesn't show as removed and added. The first version, or one whose earlier versions were deleted, has nothing before it, so every field with a value counts as added.
- **Restore** puts a version's values in the entry's form, to save as its newest version. It's on every version but the current one. A page's version also puts its parent back in the parent picker, unless that parent has been archived, deleted or moved under the page since, when the page stays where it is.
- **Delete** removes a version for good, after asking. The current version, the live one and an archived entry's versions stay, and an archived entry's versions can't be renamed either. Numbers never shift, and new versions go on from the newest.
- **Keeping fewer.** `versions.keep` in `sorlo.config.ts` caps the versions each entry keeps. After each save that writes a version, in the same transaction, the oldest that are neither named nor live are deleted, beyond the newest `keep` of them. Named versions and the live one are kept on top of the count, and so the current version always is too. An entry already over the cap shrinks at its next save. With no setting, every version is kept.

```ts
// sorlo.config.ts
export default defineConfig({
  // ...
  versions: { keep: 50 },
})
```
